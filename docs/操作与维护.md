# 统一分析平台操作与维护

## 启动

双击项目目录中的 `启动统一分析平台.cmd`。脚本只在本机启动服务，然后打开：

`http://127.0.0.1:23962/`

页面、API 和数据库服务均不监听局域网或公网地址。三个旧版 HTML 和旧云端目录仅作为只读留档，不再用于新增数据。

## 数据位置

- 正式数据库：`统一分析平台\data\lottery_tools.sqlite3`
- 自动备份：`统一分析平台\data\backups`
- 首次迁移原始档、规范化档、逐条审计和清单：`%USERPROFILE%\Documents\每天工具数据\migration_backups`
- 服务日志：`%USERPROFILE%\Documents\每天工具数据\server.log`

不要在服务运行时手工移动 SQLite 主文件及其 `-wal`、`-shm` 文件。应在页面的“数据管理”中创建备份或导出 JSON。

## 日常流程

1. 在页头切换项目，项目、模式、日期和草稿互相隔离。
2. 在“数据工作台”选择日期和模式，粘贴原始资料并解析，核对正确/错误预览后保存。
3. 历史日期默认锁定；确需修改时勾选“允许修改历史日期”。
4. 多日同目录使用“数据管理”的批量分发，每次最多 20 日，整批成功或整批回滚。
5. “详细分析”“每日统计”“一次筛选”均直接从 SQLite 真源重新计算，不保存派生统计。

## 备份与恢复

- 每次重要修改前，在“数据管理”点击“创建备份”。
- 可导出当前项目或全部项目 JSON。
- 恢复 JSON 时先创建备份，再选择导入；`合并`只替换文件明确包含的模式日，`替换`会清空文件所列项目后导入。
- SQLite 自动备份是灾难恢复副本。恢复主库前必须先停止本地服务，并保留当前主库；不要直接覆盖运行中的数据库。

## 固定业务边界

- 共 3 个项目、17 个模式；所有数据主键都包含 `project_id`。
- 大围项目的杀号与杀五码共享同日 query，但目录数据独立。
- 大围生肖从 `2026-05-21` 起使用“不包含算对”规则。
- 生肖号码表当前沿用迁移时的静态规则。跨新号码年份前必须先确认并更新规则版本，不能直接沿用旧表。
- 旧上传 EXE 仍连接旧云端，不应继续用于新增数据；新增资料统一从新页面的工作台或批量分发进入本地库。
