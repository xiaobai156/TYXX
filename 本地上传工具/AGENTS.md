# 项目工作规则（必须遵守）

适用范围：本文件所在的“本地上传工具”项目及其所有子目录。后续开发、修复、重构和代码审查开始前，必须阅读并遵守本文件；除非用户明确更改，否则持续执行。

## 1. 代码实现：ponytail full

1. 简单、复用、不过度设计；先理解需求和现有调用流程，再选择最小可行改动。
2. 优先复用项目现有代码，其次使用标准库、平台原生能力和已有依赖；不为简单需求新增抽象、框架或依赖。
3. 修复根因，并检查同一逻辑的其他调用方；不只处理截图中的单个症状。
4. 不添加未要求的功能，不修改无关逻辑，保留用户已有修改。

## 2. 回复表达：i-have-adhd

1. 先结论：开头直接说明结果、当前状态或阻碍。
2. 编号步骤：把需要用户理解或执行的事项按顺序编号，使用短句、短段落。
3. 明确下一步：清楚说明接下来由谁做什么；已经完成且无需用户操作时，明确告知。
4. 当前若没有可读取的 i-have-adhd 技能文件，仍必须执行以上用户明确指定的表达规范，不声称已加载该技能。

## 3. 冲突处理与安全验证

1. 两者的回复格式要求冲突时，以 i-have-adhd 为准；代码实现仍遵循 ponytail full。
2. 不为简短或减少代码而省略必要的安全检查、输入校验、错误处理和测试。
3. 修改业务逻辑时，补充或更新可复现问题的测试，执行相关回归；涉及打包交付时验证新版构建和自检结果。
4. 未经用户授权，不上传真实数据，不删除或改写原始 TXT，不更改原有上传位置或无关业务规则。
5. 最终说明实际改动、验证结果及下一步；未验证的部分如实标明，不把测试通过说成所有潜在问题都已解决。
